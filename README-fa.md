## چرا MemRelay

تغییر ابزار هوش مصنوعی نباید به قیمت از دست رفتن پیشرفت تمام شود.

در Codex نصفه‌کاره هستید که سهمیه تمام می‌شود. می‌خواهید در Claude Code ادامه دهید، اما آن نمی‌داند چه اتفاقی افتاده است. پس نیازها را دوباره توضیح می‌دهید، پیشرفت را دوباره شرح می‌دهید — یا کلاً رها می‌کنید.

MemRelay سوابق جلسه‌ای را که هر ابزار روی رایانه شما نگه می‌دارد مستقیماً می‌خواند و همان لحظه که می‌گویید «ادامه»، محتوای تحویل را استخراج می‌کند. **ابزار قبلی لازم نیست کاری انجام دهد — نه سند تحویل، نه کپی و چسباندن.**

## نکات برجسته

- **بدون نیاز به همکاری عامل قبلی** — از ابزار قبلی هیچ چیزی نمی‌خواهد؛ سابقه جلسه محلی آن را می‌خواند و پیشرفت، کارهای باقی‌مانده و گام بعدی را در همان لحظه استخراج می‌کند.
- **یک‌بار راه‌اندازی، بعد عادی صحبت کنید** — بعد از `memrelay setup` لازم نیست memrelay را ذکر کنید؛ در ابزارهایی که Skill یا راهنمای شروع دارند، «ادامه وظیفه XX» به‌طور خودکار فعال می‌شود.
- **پیشرفت خودکار همگام می‌شود** — با اجازه شما در hooks ابزارها نصب می‌شود؛ پیشرفت تقریباً در زمان واقعی در ایندکس محلی ثبت می‌شود و ابزار بعدی فوراً ادامه می‌دهد.
- **ابزارهای اصلی پوشش داده شده‌اند** — جلسه‌های Claude Code، Qoder، Codex، Cursor، CodeBuddy، WorkBuddy، OpenCode، ZCode، Trae و DeepSeek Harness را می‌خواند (Trae و CodeBuddy در هر دو قالب CLI و IDE).
- **بدون نیاز به LLM** — محتوای تحویل به‌صورت محلی با قواعد استخراج می‌شود؛ پیش‌فرض آفلاین و بدون کلید API؛ جستجوی معنایی برداری، خلاصه‌های جلسه و سازماندهی ترجیحات افزونه‌های اختیاری opt-in هستند (پایین را ببینید).
- **محلی‌اول و قابل بازگشت** — داده‌ها فقط در `~/.memrelay/` می‌مانند، بدون تله‌متری؛ ابزارهای دیگر فقط خواندنی هستند و هر نوشتن در یک مانیفست ثبت و قابل بازگشت است.

## نصب

به Node.js ≥ 22.16 نیاز دارد (nvm / fnm / volta / mise همه کار می‌کنند — لانچر خودش Node مناسب را پیدا می‌کند):

```bash
npm i -g memrelay    # نصب سراسری با pnpm / yarn / bun هم کار می‌کند
memrelay setup
```

`setup` این کارها را می‌کند: **تشخیص** ابزارهای نصب‌شده → **فهرست** فایل‌هایی که نوشته می‌شود (راهنمای شروع + ایندکس بلادرنگ) → **یک‌بار تأیید** → نوشتن → خودآزمایی در هر ترمینال.

> [!NOTE]
> می‌خواهید اول بدون ردپا امتحان کنید؟ `memrelay setup --undo` همه نوشته‌ها را برمی‌گرداند (داده‌ها می‌مانند)؛ با `--purge` داده‌ها هم حذف می‌شوند.

## شروع سریع

```bash
npm i -g memrelay && memrelay setup
```

سپس پروژه‌ای را باز کنید که «با ابزار دیگری نصفه‌کاره» گذاشته‌اید و در یک ابزار متصل با Skill یا راهنمای شروع بگویید:

> ادامه وظیفه XX

عامل به‌طور خودکار `memrelay resume` را اجرا می‌کند، محتوای تحویل را می‌گیرد (کدام ابزار، تا کجا، قدم بعدی چیست) و ادامه می‌دهد.

## دستورها

عامل به‌طور خودکار در جلسه اجرا می‌کند (فقط خواندن، فقط چاپ):

| دستور | کار |
|---|---|
| `memrelay resume "کلیدواژه"` | وظیفه قطع‌شده را پیدا می‌کند و تحویل را چاپ می‌کند؛ زنجیره‌های انتقال بین ابزارها هم همراه می‌آیند |
| `memrelay resume` | بدون کلیدواژه: آخرین وظیفه قطع‌شده در پروژه فعلی |
| `memrelay resume <شناسه نشست>` | پس از انتخاب از فهرست، همان نشست را دقیقاً ادامه می‌دهد؛ خروجی نشانه انتقال را دارد تا نشست جدید به زنجیره بپیوندد |
| `memrelay search "کلیدواژه"` | جستجو در جلسه‌های پروژه فعلی (متن CJK قابل جستجو است) |
| `memrelay show <شناسه جلسه> --from N` | ورق زدن سوابق خام یک جلسه |

خودتان اجرا می‌کنید:

| دستور | کار |
|---|---|
| `memrelay doctor` | خودآزمایی + ساخت/به‌روزرسانی افزایشی ایندکس جلسه (`~/.memrelay/memrelay.db`) |
| `memrelay ui` | رابط وب محلی (پایین را ببینید) |
| `memrelay embed [--status]` | پرکردن برداری: متن را جاسازی و در پایگاه محلی ذخیره می‌کند (اول جستجوی معنایی را در تنظیمات فعال کنید)؛ `--status` پیشرفت را نشان می‌دهد |
| `memrelay summarize [--status]` | خلاصه‌های جلسه: انتهای هر جلسه را با endpoint خلاصه به ۲ تا ۴ جمله پیشرفت فشرده می‌کند؛ `--status` پیشرفت را نشان می‌دهد |
| `memrelay tidy [--status\|--apply\|--undo]` | سازماندهی ترجیحات بین ابزارها: حافظه/قواعد سراسری هر ابزار را وارد، ادغام و در بلوک نشانه MemRelay بازنویسی می‌کند |
| `memrelay setup --undo` | لغو اتصال (داده‌ها می‌مانند)؛ با `--purge` داده‌ها هم حذف می‌شوند |

## منابع پشتیبانی شده

سوابق جلسه مستقیماً خوانده می‌شوند — ابزار مبدأ لازم نیست کاری انجام دهد:

| ابزار | محل جلسه‌ها روی این دستگاه |
|---|---|
| Claude Code | `~/.claude/projects/<encoded-path>/*.jsonl` |
| Qoder | `~/.qoder/projects/<encoded-path>/*.jsonl` (شامل قالب transcript IDE) |
| Codex | `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl[.zst]` (فراداده از `state_*.sqlite` فقط‌خواندنی) |
| Cursor | `%APPDATA%/Cursor/User/globalStorage/state.vscdb` (KV متن ساده، فقط‌خواندنی) |
| CodeBuddy | CLI: `~/.codebuddy/projects/…/*.jsonl`؛ IDE: `%LOCALAPPDATA%/CodeBuddyExtension/Data/…/CodeBuddyIDE/…/history/<md5 فضای کاری>/<جلسه>` (یک JSON برای هر پیام) |
| WorkBuddy | `~/.workbuddy/projects/…/*.jsonl` + فراداده `workbuddy.db` |
| OpenCode | `~/.local/share/opencode/opencode.db` |
| ZCode | `~/.zcode/cli/db/db.sqlite` |
| Trae / Trae CN | CLI از قالب سازگار Codex استفاده می‌کند؛ مخزن جلسه IDE رمزگذاری شده و از رویدادهای hook بازسازی می‌شود |
| DeepSeek Harness | `~/.dsh/sessions/<encoded-project-dir>/session-<id>/session.v4.jsonl.zstd` (zstd چندفریمی، فقط‌خواندنی) |

> [!NOTE]
> مسیرها از پوشه داده پیش‌فرض هر پلتفرم پیروی می‌کنند: ردیف‌های Cursor / CodeBuddy بالا مسیرهای Windows هستند؛ در macOS `~/Library/Application Support/…` و در Linux `~/.config/…` است. OpenCode در همه پلتفرم‌ها از `~/.local/share/opencode` استفاده می‌کند و `~` پوشه خانه کاربر فعلی است.

اتصال دو لایه دارد و همه در مانیفست ثبت و قابل بازگشت است: **Skill** (به ابزار یاد می‌دهد وقتی می‌گویید «ادامه»، memrelay را صدا بزند) در پوشه‌های skill ابزارهای Claude Code / Qoder / Codex / Cursor / CodeBuddy / WorkBuddy / Trae / Trae CN / DeepSeek Harness نصب می‌شود؛ **ایندکس بلادرنگ** (پیشرفت کار در چند ثانیه ثبت می‌شود) در Claude Code / Qoder / Codex / CodeBuddy / WorkBuddy / ZCode / Trae CN (سه‌گانه hooks؛ CLI و IDE CodeBuddy همان تنظیمات کاربر را به اشتراک می‌گذارند) و OpenCode / DeepSeek Harness (مکانیزم plugin رسمی خودشان) نصب می‌شود — dsh برای ایندکس بلادرنگ از plugin درون‌فرایندی استفاده می‌کند (محدودیت sandbox آن برای فرایند hook را دور می‌زند) و یک پل سازگاری hooks رسمی هم برای راهنمای شروع و سازگاری نصب می‌کند.

## محدودیت ها

- **فعال‌سازی خودکار به Skill یا راهنمای شروع وابسته است**: OpenCode در حال حاضر فقط plugin ایندکس بلادرنگ را دارد و راهنمای شروع ندارد؛ بنابراین باید `memrelay resume` را دستی اجرا کنید.
- **مخزن جلسه IDE Trae رمزگذاری شده است**: تنها زمانی که ایندکس بلادرنگ فعال باشد، جلسه از رویدادهای hook بازسازی می‌شود؛ اگر فقط Skill فعال باشد و ایندکس بلادرنگ نه، جلسه‌های گذشته خوانده نمی‌شوند.
- **فقط جلسه‌های محلی**: همگام‌سازی بین دستگاه‌ها وجود ندارد؛ ابزارهای پشتیبانی‌نشده یا جلسه‌های رمزگذاری‌شده بدون جریان رویداد خوانده نمی‌شوند.

## رابط وب

```bash
memrelay ui
```

رابطی محلی که فقط روی `127.0.0.1` گوش می‌دهد باز می‌کند (توکن یک‌بارمصرف؛ داده‌ها از دستگاه خارج نمی‌شوند). پیش‌فرض پورت ثابت `4823` است (در صورت اشغال، تصادفی)؛ تم و زبان در localStorage مرورگر ذخیره و در اجرای بعدی بازیابی می‌شوند.

- **داشبورد**: نمای کلی وضعیت، وظایف آماده ادامه، وظایف اخیر، فعالیت ۱۴ روز گذشته و توزیع ابزار/پوشه
- **فهرست وظایف**: زنجیره‌های انتقال بین ابزارها در یک وظیفه ادغام می‌شوند؛ گروه‌بندی بر اساس پوشه، مرتب‌سازی بر اساس آخرین فعالیت، وضعیت بلادرنگ
- **جزئیات وظیفه**: ریل انتقال عمودی + پیش‌نمایش تحویل + کپی یک‌کلیکی پرامپت تحویل
- **سه پوسته**: مینیمال / کمیک / پیکسل × روشن / تیره / سیستم؛ تم و زبان ذخیره می‌شوند
- **۱۱ زبان رابط**: چینی ساده‌شده / English / چینی سنتی / 日本語 / 한국어 / Español / Français / Deutsch / فارسی / Português (BR) / Bahasa Indonesia
- **مرور و جستجوی جلسه**: جستجوی متن کامل (شامل CJK)، پرش به محل تطابق با برجسته‌سازی
- **مدیریت اتصال / استثناهای حریم خصوصی / سطل بازیافت / اصلاح دستی** (تغییر نام، علامت‌گذاری انجام‌شده، تقسیم و ادغام زنجیره‌ها)

## افزونه‌های اختیاری

جستجوی معنایی، خلاصه‌های جلسه و سازماندهی ترجیحات به‌طور پیش‌فرض خاموش هستند. هر کدام تنظیمات endpoint مستقل خود را در صفحه تنظیمات `memrelay ui` دارند (مستقل از هم و می‌توانند به upstream متفاوت اشاره کنند). قبل از ارسال، کلیدها پوشانده می‌شوند؛ اگر جستجوی معنایی یا خلاصه‌ها شکست بخورند، به استخراج مبتنی بر قاعده موجود برمی‌گردند و اگر سازماندهی شکست بخورد، چیزی بازنویسی نمی‌شود.

- **جستجوی معنایی**: یک کانال معنایی اضافه می‌کند تا جستجوی «صفحه ورود» جلسه‌هایی را هم پیدا کند که "auth page" نوشته‌اند. فقط متن user/assistant جاسازی می‌شود و فقط `/embeddings` سازگار با OpenAI پشتیبانی می‌شود. مقیاس مرجع: حدود ۲۵۰ جلسه ≈ ۲ میلیون کاراکتر ≈ ۰٫۰۳ دلار. محتوای بدون تغییر با تطبیق هش رد می‌شود؛ با تغییر مدل/میزبان بازسازی یک‌کلیکی ممکن است. [طراحی](docs/vector-search.md)
- **خلاصه‌های جلسه**: برای هر جلسه یک خلاصه پیشرفت ۲ تا ۴ جمله‌ای می‌سازد و در خروجی تحویل (`## 任务摘要（AI 生成）`)، فهرست و جزئیات وظایف و مرور جلسه‌ها نمایش می‌دهد. مواد فقط شامل عنوان، سیگنال‌های وضعیت و حدود ۲۰ پیام آخر انتهای جلسه (≤8KB) است؛ استدلال و خروجی ابزارها ارسال نمی‌شوند. برای ۲۵۰ جلسه حدود ۱ میلیون توکن. مواد بدون تغییر رد می‌شود؛ با تغییر مدل/میزبان بازسازی یک‌کلیکی ممکن است. [طراحی](docs/llm-summary.md)
- **سازماندهی ترجیحات**: حافظه/قواعد سراسری هر ابزار را فقط‌خواندنی وارد می‌کند، تکرارها و تناقض‌ها را ادغام می‌کند و بلوک نشانه MemRelay را بازنویسی می‌کند. فقط بلوک‌های نشانه را تغییر می‌دهد، قبل از نوشتن پشتیبان می‌گیرد، قابل بازگشت است و تناقض‌ها را نمایش می‌دهد نه اینکه خودکار حل کند؛ هنگام اجرای `memrelay ui` تغییرات منابع خودکار بررسی می‌شوند. [طراحی](docs/tidy.md)

نگهداری: `memrelay embed` / `memrelay summarize` / `memrelay tidy` برای پرکردن کامل (قابل توقف و ادامه)؛ `memrelay ui` هنگام اجرا در پس‌زمینه پر/بررسی می‌کند.

## حریم خصوصی و امنیت

- داده‌ها فقط در `~/.memrelay/` روی رایانه شما هستند؛ بدون تله‌متری؛ به‌طور پیش‌فرض به هیچ سرویس ابری وابسته نیست.
- فایل‌های ابزارهای دیگر فقط خوانده می‌شوند؛ نوشتن محدود به تنظیمات Skill / hooks و `~/.memrelay/` است و همه در مانیفست ثبت و قابل بازگشت هستند.
- قبل از ایندکس و خروجی، کلیدها شناسایی و پوشانده می‌شوند (کلید API، توکن، کلید خصوصی، رشته اتصال و…).
- وقتی جستجوی معنایی، خلاصه‌های جلسه یا سازماندهی ترجیحات فعال باشند، متن/حافظه مرتبط (با کلیدهای پوشانده‌شده) به میزبان‌هایی که پیکربندی کرده‌اید ارسال می‌شود (هر سه قابلیت endpoint مستقل دارند)؛ پیش‌فرض هر سه خاموش است.
- سرور رابط فقط روی `127.0.0.1` گوش می‌دهد، توکن دسترسی می‌خواهد و هدر Host را بررسی می‌کند؛ درخواست‌های نوشتن Originهای cross-origin را هم رد می‌کنند.
- hookهای IDE Trae در sandbox خود Trae اجرا می‌شوند و فقط می‌توانند رویدادهای خام را در `hooks_env` Trae بگذارند؛ کلیدهای رایج (`sk-`، توکن GitHub، کلید AWS، فیلدهای `password/token`) ابتدا در sandbox پوشانده می‌شوند، اما محتوای خارج از این قواعد ممکن است در آن کپی بماند. با لغو اتصال این فایل‌ها حذف می‌شوند. اگر این برایتان مهم است، فقط Skill Trae را فعال کنید و ایندکس بلادرنگ را خاموش بگذارید.

## توسعه

مخزن یک pnpm workspace است: `packages/cli` بسته اصلی CLI (محصول منتشرشده) و `packages/ui` رابط وب (خروجی build در `dist/ui` CLI ادغام می‌شود).

```bash
pnpm install
pnpm typecheck     # tsc --noEmit برای هر دو بسته
pnpm test          # تست‌های واحد + یکپارچه vitest (e2e جداگانه، پایین)
pnpm build         # ابتدا tsdown → packages/cli/dist/cli.mjs، سپس رابط به packages/cli/dist/ui
cd packages/cli && npm link   # اختیاری: قرار دادن memrelay در PATH (معادل npm i -g memrelay)
node packages/cli/test/e2e/bootstrap.mjs   # end-to-end لانچر
```

طراحی و برنامه‌های تکرار: [docs/architecture.md](docs/architecture.md).
